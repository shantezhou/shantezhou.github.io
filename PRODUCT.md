# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

static HTML/CSS only — user explicitly pinned this ("All it needs to be done in is HTML and CSS"). No JavaScript, no build step, no framework.

## Users

Readers of technical writing — peers, students, and curious practitioners in AI, chemistry, and mathematics. They arrive from a shared link, read one post, maybe browse the index. The author (Shante Zhou) is also a primary user: adding a new post must be as simple as copying an HTML file and adding one link on the home page.

## Product Purpose

Personal technical blog for Shante Zhou. Posts are either teaching material or learning-in-public notes, mostly on AI, chemistry, and mathematics. Success: the writing is effortless to read, and publishing a new post takes minutes.

## Operating Context

Posts will contain technical elements: code blocks, inline code, mathematical notation, lists, and occasional figures/tables. The layout must handle these gracefully from day one.

## Capabilities and Constraints

- Home page = list of posts; each links to a standalone post page.
- No CMS, no generator: publishing = hand-writing an HTML file from a template.
- Once the style is settled, it gets encapsulated in a Markdown style-guide file (STYLE.md) so future posts stay consistent (user-requested workflow).
- No real posts exist yet; the first post is a style specimen the user will review and adjust.

## Brand Commitments

User-pinned, binding: white background, black text, ultra-minimal ("literally nothing at all"). Typeface: JetBrains Mono ("for the text… let's just do JetBrains"). Blog title/name: **Shante Zhou** (confirmed via interview).

## Evidence on Hand

No posts, no assets, no logo. Do not fabricate post content presented as real work; the specimen post must be honest about being a demo/specimen or contain genuinely correct technical content.

## Product Principles

1. Reading comfort outranks everything except the pinned minimalism.
2. One file per post; zero tooling — the site must stay editable by hand forever.
3. Technical content (code, math, tables) is first-class, not an afterthought.
4. Restraint is the identity: every addition must justify itself against "literally nothing at all."
